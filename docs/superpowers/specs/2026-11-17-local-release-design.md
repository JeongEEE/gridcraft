# Grid 로컬 배포 설계

사용자 결정: Mac과 Windows에서 각각 저장소를 받아 네이티브 빌드하고 GitHub에는
완성된 릴리스 파일만 업로드한다. Actions runner를 호출하거나 배포 브랜치를 푸시하지 않는다.

## 접근과 선택

- 채택: OS별 실행 파일과 공통 Python 3.11+ 오케스트레이터. 같은 버전·커밋의 초안에
  각 OS 패키지와 해시를 기록한 빌드 증빙을 추가한다. 두 OS가 모여야 기존 키로 서명하고 공개한다.
- 제외: GitHub Actions 빌드(사용자가 제외), Mac에서 Windows 크로스 빌드(사용자는 Windows PC 사용).

## 동작

- `deploy-macos.sh`, `deploy-windows.ps1`; 기존 `deploy.sh`는 Mac 진입점 호환 별칭.
- 버전 생략 시 현재 미공개 버전을 이어 사용한다. 현재 버전이 이미 공개됐으면 다음 패치를
  준비·커밋·푸시한다. 두 번째 PC는 먼저 `my-custom`을 pull하고 같은 버전으로 실행한다.
- 공개된 버전·다른 SHA의 자산이 있는 초안·태그·미완성 추적 파일은 거부한다. 원격 변경을 자동 병합하지 않는다.
- 빌드 시작 전, 파일·태그가 전혀 없는 미공개 초안은 같은 버전의 이전 조상 커밋에서 현재
  커밋으로 갱신할 수 있다. 기존 Source commit 기록·조상 관계·이전 버전과 변경 여부를
  확인하고 초안 상태를 유지한다. `--finalize`는 이 복구를 수행하지 않는다.
- 빌드 산출물은 임시 폴더에 만들고 소스 SHA·버전·글꼴 고정 커밋·검증·파일 해시를 증빙에 기록한다.
- 글꼴은 `storytold/craft-fonts`의 `b076417b5880bd4154bd22f00695b1d28c6bea83`을 사용한다.
- 각 PC는 자기 플랫폼 파일과 증빙만 초안에 업로드한다. 같은 SHA의 재시도는 가능하지만
  다른 플랫폼 파일을 지우거나 공개된 파일을 덮어쓰지 않는다. 두 PC 동시 실행은 지원하지 않는다.
- `--finalize`는 빌드 없이 두 OS 산출물을 내려받고 증빙·해시를 확인한다. 기존 Rust 서명기를
  사용하고 체크섬을 작성한 후 서명·manifest·체크섬을 업로드한다. 총 자산은 기존 7개와 증빙 2개다.
- 키는 `GRID_UPDATE_KEY_FILE` 또는 저장소 밖 기본 경로에서만 읽는다. Windows 업로드에는 키가
  없어도 된다. 키가 있는 PC에서 마무리한다. 키 값을 인자·로그·증빙에 넣지 않는다.
- `--draft`는 공개 질문을 생략한다. 그 외에도 완전한 검증 뒤 기본 거절인 공개 질문을 한 번 한다.
- `--dry-run`은 파일·git·원격을 변경하거나 네트워크를 호출하지 않는다.
- Windows 개인 PC에서는 MSI 설치·제거 회귀를 자동 실행하지 않는다. 패키지의 기존 정적
  설치 정책 검사, updater 테스트, CLI 계산·저장·재열기를 실행한다. 실제 MSI 설치·업데이트
  검증은 별도의 깨끗한 Windows 환경용 기존 스크립트로 수행한다.
- 포크 전용 Actions workflow는 삭제하고 upstream workflow는 유지한다. 이번 작업은 배포하지 않는다.

## 검증

실제 임시 git 원격과 로컬 파일을 사용하고 GitHub·컴파일러 경계만 통제한 통합 테스트로
두 OS 업로드 순서, 버전 재사용, 서명 마무리, 다른 소스·해시·API 실패·작업 중 변경을 확인한다.
Mac에서 PowerShell 파싱/진입점과 로컬 Mac 패키징을 확인하고 Windows 실제 네이티브 빌드
실행 여부는 구분해 보고한다. 기존 아랍어 커서 실패 한 건은 기존 규약을 따른다.
