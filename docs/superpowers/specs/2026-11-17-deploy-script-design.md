# Grid 배포 스크립트

사용자는 다이어리 프론트처럼 `./deploy.sh` 한 번으로 포크 배포를 진행하고, GitHub Actions의 macOS·Windows 빌드를 터미널에서 확인하기를 원한다. 대화에서 다음 흐름으로 바로 구현하도록 승인했다.

- 인자가 없으면 현재 버전의 다음 패치 버전, `./deploy.sh 0.19.6`이면 지정 버전으로 준비한다.
- 현재 `my-custom`의 커밋된 소스를 기준으로 버전만 변경·커밋·푸시하고, `my-custom-release`를 fast-forward한다. 다른 작업의 미완성 소스나 인덱스는 포함하지 않는다.
- 정확한 소스 SHA의 포크 workflow 실행을 찾아 진행 상태를 보여 주고 기다린다. 실패하면 중단하고 로그 확인 방법을 알려 준다.
- 성공한 실행의 릴리스 초안·소스 커밋·필수 자산을 확인한 뒤 마지막 공개 여부를 한 번 묻는다. 동의해야 공개한다. 입력 종료·취소는 초안을 유지한다.
- `--dry-run`은 버전·git·원격 상태를 변경하지 않고 예정된 절차를 출력한다. `--draft`는 공개 질문 없이 초안에서 끝낸다.
- 중간 실패 후 같은 버전으로 다시 실행할 수 있다. 이미 공개된 버전은 덮어쓰지 않는다.
- 이번 개발에서는 배포를 실행하지 않는다. 테스트는 임시 git 저장소와 통제된 외부 CLI 응답으로 진행한다.

## 접근 방식

기존 GitHub Actions는 두 OS 빌드·설치 시험·업데이트 서명을 이미 담당한다. 로컬에서 이를 다시 구현하는 대신, 루트의 짧은 Bash 진입점과 Python 표준 라이브러리 오케스트레이터로 기존 workflow를 연결한다. 복잡한 JSON·오류·재시도 처리를 Bash에 흩뜨리지 않고 기존 packaging 도구의 Python 사용 범위를 따른다. 사용자는 추천한 이 흐름을 선택했다.
