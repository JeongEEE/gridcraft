# Grid 자동 업데이트 설계

사용자가 승인한 흐름은 포크 공개 릴리스 확인 → 백그라운드 다운로드 → 준비 완료 알림 → 저장 확인 → 재시작하며 설치다. Windows와 macOS를 지원한다. main과 원본 updater는 수정하지 않는다.

## 접근과 선택

기존 craft-update 설치기는 원본 Apple Team ID와 Windows Authenticode를 고정한다. 이를 끄면 포크 파일의 인증이 사라진다. Sparkle와 Windows 별도 프레임워크는 두 구현과 네이티브 연동을 추가한다. 따라서 기존 HTTP·릴리스 파서·프로세스 도구는 재사용하고, 포크 전용 Rust crate가 서명 검증과 설치를 담당한다. 이 선택은 구현자의 판단이다.

## 신뢰 경계

릴리스에 `GridUpdate.json`과 `GridUpdate.sig`를 추가한다. Ed25519 서명은 JSON 원문 전체를 인증한다. 고정 repository, schema, numeric version, tag, 플랫폼별 정확한 파일명·크기·SHA256을 검사한다. URL은 해당 포크의 해당 태그에서만 생성한다. 설치 helper는 다운로드 이후에도 서명과 파일 해시를 다시 검사한다. 공개키는 소스에 고정하고 개인키는 GitHub Actions secret에만 둔다. 키가 없거나 검증에 실패하면 설치하지 않는다. 기존 OS 서명과 공증은 별개이며 OS 보안을 해제하지 않는다.

## 수명 주기

기동과 Help 메뉴에서 확인하고 장시간 실행 시 6시간마다 다시 확인한다. 다운로드는 작업 스레드에서 진행하며 진행률과 실패/재시도를 표시한다. 다운로드만으로 설치가 예약되지 않는다. 준비 알림의 Later는 준비 파일을 유지하고, Restart는 기존 request_quit 저장 확인을 호출한다. Cancel하면 예약을 해제한다. on_exit에서 명시적으로 선택한 예약만 helper로 넘긴다. 종료에 실패하면 교체하지 않는다.

Mac은 설치된 쓰기 가능한 Grid.app만 대상으로 하고 DMG·translocation·개발 빌드는 수동 안내한다. 새 DMG를 readonly로 마운트하고 번들 ID·버전·엄격한 codesign을 확인한 후 같은 부모 디렉터리에 복사한다. 기존 번들을 백업으로 rename한 뒤 새 번들을 rename한다. 실패하면 원래 번들을 복원한다.

Windows는 등록된 설치 문맥을 유지해 MSI를 실행한다. 관리자 설치는 OS 권한 승인이 필요할 수 있다. 포터블은 서명된 ZIP의 안전한 상대 경로만 풀고 기존 배포 파일별 백업과 되돌리기를 사용한다. 사용자 추가 파일과 설정은 건드리지 않는다. helper는 현재 실행 파일의 복사본으로 실행하고 부모 종료를 기다린다. 파일 교체/설치 실패는 다음 실행에서 알린다. MSI의 트랜잭션 롤백을 재사용한다.

## 배포와 검증

기존 draft만 갱신하며 공개 발행은 별도 승인이다. 업데이트 목록은 모든 패키지 생성 이후 서명한다. 기존 설치자는 updater 포함 버전을 한 번 수동 설치해야 한다. 개인키 생성·GitHub secret 등록은 저장소 규칙상 별도 확인이 필요하므로 코드·테스트를 먼저 준비한다.

잘못된 서명·저장소·태그·버전·플랫폼·크기·해시, 경로 탈출, 실행 중 부모, 저장 취소, 부분 파일 교체 실패를 회귀 검사한다. Mac 실제 번들 교체와 Windows MSI/포터블 교체를 격리 환경에서 검사한다. 원본 Arabic caret 기준선 실패는 따로 보고한다.
