# Grid Fork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grid를 원본과 분리된 Windows/macOS 개인 앱으로 빌드하고 포크 릴리스 초안을 준비하며 유지보수 위키를 만든다.

**Architecture:** Rust crate·엔진 명령 이름은 유지한다. UI 표시, 설치 식별자, 설정과 업데이트 저장소를 분리하고 포크 전용 배포 workflow를 추가한다.

**Tech Stack:** Rust 1.95, egui, craft-update, Bash, WiX/PowerShell, GitHub Actions, Markdown.

**Spec:** `docs/superpowers/specs/2026-11-14-grid-fork-design.md` (사용자 승인 2026-11-14).

## Global Constraints

- 표시 이름 `Grid`, 유지관리자 `JeongEEE`, 업데이트 저장소 `JeongEEE/gridcraft`.
- macOS 번들 ID `io.github.jeongeee.grid`; 원본과 설정·설치·업데이트를 분리한다.
- `main`은 업스트림 동기화 전용, 모든 개인 수정은 `my-custom`에서 한다.
- Windows x64 MSI/ZIP, macOS universal DMG/CLI ZIP을 지원한다.
- 유료 서명을 구매하지 않는다. 두 OS 모두 자동 확인과 알림·다운로드만 제공하고 설치·재시작은 하지 않는다.
- 원본 저작권 고지는 보존하고 ArtCraft 브랜드 자산은 배포물에서 제거한다.
- 현재 설치된 원본 앱과 사용자 문서는 덮어쓰지 않는다.
- 첫 릴리스는 draft로 만든다. 공개 발행은 산출물 검증 뒤 사용자 확인을 받는다.

## Review Focus

- 업스트림 업데이트가 개인 앱에 설치되면 안 된다: 업데이트 repo와 App id/asset stem을 함께 확인한다.
- 원본이 설치된 PC에서 registry/UpgradeCode/설정 폴더가 충돌하면 안 된다.
- 개발 빌드·미서명 Windows의 업데이트 한계를 숨기거나 서명 검사를 우회하면 안 된다.
- 한 플랫폼 빌드가 실패한 릴리스는 완성된 것으로 표시하면 안 된다.
- 위키에는 검증 결과와 설계/예정을 구분하고 동기화 결과물은 직접 편집하지 않는다.

### Task 1: Grid 앱 식별자, 패키징 및 포크 릴리스

**Files:**
- Modify: `apps/gridcraft/{src/main.rs,src/native_menu.rs,src/print.rs,build.rs,tests/mac_menu_appkit.rs}`.
- Modify: `crates/ui-egui/src/{lib.rs,dialogs/about.rs,dialogs.rs,backstage.rs,ribbon/*,app/*,i18n/*}` 중 실제 표시 이름이 있는 파일.
- Modify: `packaging/macos/{package.sh,Info.plist.in}`, `packaging/windows/{package.ps1,gridcraft.wxs,install-policy.json,install-policy.wxi,sign.ps1}` 및 기존 설치 검증 테스트.
- Create: `crates/ui-egui/tests/fork_identity.rs`, `.github/workflows/release-custom.yml`, `docs/custom-release.md`.
- Modify: `AGENTS.md`, `README.md`, `Cargo.toml`, `Cargo.lock`, `ATTRIBUTION.md` (브랜드 제거가 필요하면), `docs/releasing.md`의 포크 안내.

**Interfaces:**
- Consumes: `craft_update::app::App`, 기존 CLI와 플랫폼 패키징 스크립트.
- Produces: `Grid.app`, 독립 Windows 설치, 포크 저장소를 확인하는 updater, 포크 전용 draft release.
- 구현 확인으로 updater가 asset을 `App.id`로 선택하므로 외부 stem은 `grid`로 분리한다.
  Cargo crate와 빌드 원본 바이너리는 `gridcraft`/`gridcraft-cli` 그대로 두고 패키징 때 바꾼다.

- [x] **Step 1:** 기존 `UPDATE_APP`에 대한 회귀 테스트를 먼저 쓴다. `name == "Grid"`, `repo == "JeongEEE/gridcraft"`, `id == "grid"`, `bundle_id() == "io.github.jeongeee.grid"`를 검증한다. `cargo test -p gridcraft-ui-egui --test fork_identity`가 원본 값 때문에 실패하는지 확인한다.
- [x] **Step 2:** UI, 네이티브 메뉴, 앱 설정 경로와 updater identity를 변경한다. 저작권과 engine API는 유지한다. 테스트가 통과하고 CLI의 수식·XLSX 동작이 유지되는지 확인한다.
- [x] **Step 3:** macOS 번들/패키지 이름과 ID, Windows 설치 GUID·registry·바로가기·파일 이름을 분리한다. 기존 installer contract checker를 Grid 값으로 갱신한다. macOS plist와 Windows policy 양쪽이 같은 fork identity를 가지는 회귀 검증을 추가한다.
- [x] **Step 4:** macOS/Windows만 빌드하고 체크섬과 draft release를 만드는 포크 전용 workflow를 작성한다. `my-custom-release` push와 수동 실행을 지원하며, 포크 owner guard와 실패 시 릴리스 생성을 막는 job 의존성을 둔다. Rust/action 버전은 실제 공식 소스의 고정 ref를 사용한다.
- [x] **Step 5:** 포크 버전을 `0.19.2`로 시작한다. 앱·태그·설치 파일의 버전은 일치시킨다. 후속 버전 증가는 `cargo xtask version set` 절차로 문서화한다.
- [ ] **Step 6:** `cargo xtask ci`, macOS release build·패키징·서명 검증·CLI smoke test를 실행한다. Windows는 fork CI에서 실제 MSI와 ZIP을 빌드하고 검사한다. 실제 실행 결과만 기록한다.
- [ ] **Step 7:** 독립 리뷰를 받고 본 Task 경로만 stage하여 `feat: Grid 개인 포크 앱과 배포 구성 추가`로 커밋·푸시한다. 사용자가 승인한 배포 흐름에 따라 `my-custom-release`에 반영해 첫 draft를 준비한다. `main`은 수정하지 않는다.
